# Порядок работы над upo-lab1

Общий файл контекста для всех участников. Читать в начале каждой сессии, до первого действия. Обновляется по команде Хозяина; кто вносит правку, коммитит её отдельным коммитом.

Проект: учебная программа «Предварительная обработка» – лабораторная работа по полиномиальному сглаживанию измерений дальности и радиальной скорости (замена прежней Obr rabot.exe). Java 8, Maven, Swing, формы NetBeans. Репозиторий: github.com/sergs-s/upo-lab1.

## 1. Роли

| Кто | Где работает | Что делает |
|---|---|---|
| **Хозяин** (автор, преподаватель) | NetBeans, локальный клон `D:\Учебное пособие\Готовое\ЛР1 Java\upo-lab1` | Контролирует, ставит новые задачи, принимает решения по спорным вопросам, проверяет результат в NetBeans, собирает jar, отправляет и сливает ветки. |
| **Боба** (архитектор) | Cowork; читает локальный клон Хозяина, в GitHub доступа не имеет | Разбирает задачу Хозяина, определяет путь решения, ставит задание Бибе, проверяет отчёт и код Бибы, правит руководства (docx) и прочие документы в папке «Готовое». |
| **Биба** (программист, сеньор) | Claude Code в облаке, работает с GitHub | Программирует по заданию Бобы, проверяет сборку и проверочные программы, коммитит и отправляет на GitHub, пишет итоговый отчёт. |

Боба и Биба напрямую не общаются: задания и отчёты передаёт Хозяин.

## 2. Порядок прохождения задачи

1. Хозяин ставит задачу Бобе.
2. Боба уточняет у Хозяина неясное, выбирает решение и пишет задание Бибе: что сделать, где, какие ограничения, как проверить, что вернуть в отчёте.
3. Хозяин передаёт задание Бибе.
4. Биба выполняет, коммитит, отправляет в master, пишет отчёт (раздел 4).
5. Хозяин передаёт отчёт Бобе; Хозяин делает `git pull`, Боба проверяет код в локальном клоне и отвечает на вопросы Бибы.
6. Хозяин проверяет в NetBeans. Замечания идут снова через Бобу.
7. После приёмки Боба по команде Хозяина правит руководства и обновляет этот файл.

## 3. Общие правила

- Вопрос – это вопрос: сначала ответ словами, действия только по явной команде. Отсутствие команды означает «не трогать».
- Всё по-русски: интерфейс, комментарии, сообщения коммитов, ответы. Длинное тире (U+2014) не использовать нигде, только короткое «–».
- Коротко, по существу. Ошибку не объяснять, а исправить.
- Спорное не решать самостоятельно – спросить (Биба – через отчёт, Боба – у Хозяина).
- Исходные материалы курса не трогать; в документах править только то, что сами положили в «Готовое».

## 4. Правила для Бибы

### Git
- Работаем прямо в **master**. Ветка master-vtnokt больше не используется (совпадает с master; не трогать и не удалять).
- Каждый законченный шаг: коммит (сообщение по-русски, по существу) и push в master. Force-push не делать, pull request не создавать, новые ветки не заводить.
- Если push в master отклонён (нет прав у облачной среды) – сразу сообщить и ждать указаний, обходных путей не искать.
- Push иногда обрывается (503 / «remote end hung up») – повторять с паузой и сверять `git ls-remote origin master` с HEAD.

### Код
1. Java 8: без var, List.of, текстовых блоков, Files.readString и т. п. Сборка: `javac --release 8 -encoding UTF-8` (Maven может быть недоступен).
2. Пары .form + .java NetBeans (InputPanel, ResultsPanel, NotebookPanel, TeacherPanel, ModeParamsPanel, LoginPanel, WelcomePanel, TestPanel, MainFrame) не должны расходиться. Любая правка initComponents() делается и в .form:
   - только GroupLayout (группы type="102"/"103", EmptySpace), у компонентов нет Constraints, FlowLayout не использовать;
   - каждый компонент из раскладки контейнера объявлен его потомком в SubComponents;
   - сложные свойства (модели спиннеров и списков, рамки, шрифты) – в customize(), а не в форме;
   - обработчики из .form существуют в .java и наоборот;
   - блок Variables declaration – по алфавиту.
   После правки проверять форму скриптом: все id из раскладки объявлены, все обработчики есть в коде. Образец – NotebookPanel.
3. Окна без форм, собранные кодом: TaskFrame, HelpFrame, SummaryFrame, SmoothingFrame, JournalFrame. Поведение как у SummaryFrame: один экземпляр, вызвавшее окно на время показа setEnabled(false), окно нельзя свернуть.
4. Расчётное ядро (core/, math/) не менять; режим error.mode = anchor | averaged | legacy не трогать; target/ и pom.xml не трогать; файлы целиком не переформатировать.

- Все в src/test/java, с main, без JUnit.

- Запуск: LC_ALL=C.UTF-8, java -Dfile.encoding=UTF-8; программам с окнами нужен xvfb-run -a. Ресурсы скопировать из src/main/resources в каталог классов.
- Снимки окон смотреть самому перед коммитом.

### Итоговый отчёт Бибы
Отчёт начинается с заголовка «Отчёт Бибы Бобе: <суть задания>».
1. Что сделано – по пунктам задания, с хешами коммитов.
2. Какие файлы изменены (.form и .java – парами).
3. Чем проверено и с каким результатом (сборка, проверочные программы, снимки окон).
4. Что не сделано или сделано иначе, чем в задании, и почему.
5. Вопросы к Бобе и Хозяину.
6. Новые подписи, сообщения и настройки, видимые пользователю (дословно) – нужны для руководств.

Измерение одной скорости – как в прежней программе (m – степень полинома скорости). σV по умолчанию 0,01 м/с. Скорость и совместная обработка – только ручной ввод, вариантов нет.
2. Окно «Сглаживание измерений дальности полиномом» (ui/SmoothingFrame, расчёт – ui/SmoothingModel), вызов – кнопка «Наглядно: сглаживание измерений» в «Сведениях из теории».
   - Данные: вариант 1 (H = 1000 км, до трассы 50 км, σR = 10 м); зона видимости при угле места ≥ 7° длится 836,8 с; 60 измерений с шагом 14,18 с; полином 1-й степени по каждым 10 измерениям.
   - Анимация: КА движется плавно (25 кадров/с); измерение – красная вспышка синей линии визирования; подписи Rист (синим, непрерывно) и Rизм (красным, в момент измерения); антенна-тарелка; границы зоны – зелёные штрихи, границы пройденных участков – чёрные штрихи.
   - График R(t): разброс точек увеличен до σ = 50 км, в таблице – настоящие числа.
   - Таблица: № | t, с | Rист | Rизм | Rизм − Rист | полином R*(t) (одна ячейка на 10 строк) | R* | R* − Rизм | Rист − R*. Красным – величины, неизвестные измерителю. Под таблицей – СКО по участкам.
   - Управление: «Шаг», «Пуск», «Пауза», «Заново», скорость 0,5–4 такта/с.
3. Журнал обучающихся (model/Journal, model/JournalRecord, ui/JournalKeeper, ui/JournalFrame).

   - Повреждённые и поддельные записи удаляются молча, записи старше 30 дней – при запуске.
   - После положительной оценки повторный вход восстанавливает работу без контроля; после неудовлетворительной – не допускает, пока преподаватель не удалит запись.
